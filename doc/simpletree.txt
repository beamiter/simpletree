1. INTRODUCTION                                             *simpletree*

SimpleTree is a Vim 9 file tree backed by an asynchronous Rust directory
scanner.  It provides a collapsible workspace root, active-file reveal,
modified-buffer marks, path-stable selection, editor-window reuse, and file
operations.

The backend bounds concurrent blocking scans, emits chunked results, understands
Git ignore rules, and supports version and capability discovery.  The user
interface and messages are currently primarily Chinese.  SimpleTree uses Vim9
script and does not support Neovim.

==============================================================================
2. REQUIREMENTS                              *simpletree-requirements*

- Vim 9.0 or newer with +job, +channel, and +float.
- Rust 1.88 or newer and Cargo to build the backend.
- Bash for install.sh; native Windows installation is not currently covered.
- A Nerd Font and a system trash provider are optional.

Check Vim with: >

  :echo has('job')
  :echo has('channel')
  :echo has('float')
<
All three values must be 1.

==============================================================================
3. INSTALLATION                                  *simpletree-install*

VIM-PLUG ~
>
  call plug#begin()
  Plug 'beamiter/simpletree', { 'do': './install.sh' }
  call plug#end()
<
Then run :PlugInstall.  Use :PlugUpdate for later updates.

VIM NATIVE PACKAGE ~
>
  git clone https://github.com/beamiter/simpletree.git \
    ~/.vim/pack/plugins/start/simpletree
  ~/.vim/pack/plugins/start/simpletree/install.sh
<
install.sh resolves the repository from its own location, uses Cargo.lock,
pins an in-repository target directory and native Rust target, verifies the
new binary with --version, and atomically replaces only
lib/simpletree-daemon.

The plugin directory must be on 'runtimepath'.  SimpleTree searches each entry
under lib/ first, then target/release/ and target/debug/ for development use.

4. COMMANDS                                      *simpletree-commands*

                                                     *:SimpleTree*
:SimpleTree [directory]
        Open or close the tree in the current tab page.  An optional directory
        becomes the root.  See |simpletree-tabpages|.

                                                     *:SimpleTreeRefresh*
:SimpleTreeRefresh
        Clear the tree cache and rescan.

                                                     *:SimpleTreeReveal*
:SimpleTreeReveal [path]
        Reveal the current active file, or an explicit file/directory below
        the existing root. A relative path is always resolved against the tree
        root, independent of :pwd or :lcd. Required ancestors are expanded
        asynchronously and only the newest reveal may move the selection.
        The lexical path and every ancestor after symlink resolution must stay
        inside the workspace, including paths that escape and later re-enter;
        missing or escaping paths leave selection, expansion state and render
        epoch unchanged. Completion enumerates relative paths from the tree
        root (not :lcd), escapes spaces, and refuses outside/symlink-escaping
        parents and candidates before directory traversal.

                                                     *:SimpleTreeClose*
:SimpleTreeClose
        Flush the current width state and close the current tab page's tree
        window, or every tree window when this tab page has none.

                                                     *:SimpleTreeDebug*
:SimpleTreeDebug
        Print root, window, backend, pending-request, cache state, and a compact
        rendering-statistics summary.

                                                     *:SimpleTreeStats*
:SimpleTreeStats[!]
        Report session-local render count, last/maximum/average duration,
        visible and actually rewritten lines, successful setbufline() /
        deletebufline() calls, subtree-cache hit/miss ratio, epoch
        invalidations, and discarded cache slices. With [!] reset only the
        counters. Reading or resetting never renders, advances the epoch, or
        invalidates a subtree, so observation does not manufacture misses.

                                                     *:SimpleTreeHealth*
:SimpleTreeHealth
        Check required Vim features, normalized configuration ranges, the
        backend executable, and detected trash and clipboard providers.

        Also reported: whether lib/simpletree-daemon is older than the Rust
        sources shipped beside it — the usual state after a plugin-manager
        update that did not rebuild, whose remedy is ./install.sh followed by
        |:SimpleTreeRestart|; the outcome of the most recent git-status query,
        including the backend's own error text when it failed; and the live
        session — root, tree windows, pending scans, in-flight callbacks and
        the first directory whose scan failed.  Git status is reported from
        that last outcome, not from the capability bit, so a root outside any
        repository now says why instead of claiming to be active.

                                                     *:SimpleTreeVersion*
:SimpleTreeVersion
        Run the discovered backend with --version and display the result.

                                      *:SimpleTreeToggleAutoRefresh*
:SimpleTreeToggleAutoRefresh
        Toggle |g:simpletree_auto_refresh| for the current Vim session.

                                       *:SimpleTreeToggleAutoFollow*
:SimpleTreeToggleAutoFollow
        Toggle |g:simpletree_auto_follow| for the current Vim session.

                                                *:SimpleTreeSearch*
:SimpleTreeSearch {query}
        Ask the backend for a recursive filename search below the current
        root and put the matches into the quickfix list.  Requires a backend
        that advertises the "search" capability.  Substring matching is the
        default; call simpletree#Search({query}, 'fuzzy') for ordered
        subsequence matching.

                                              *:SimpleTreeMarkClear*
:SimpleTreeMarkClear
        Clear every mark.  Same as gM in the tree.

                                                     *:SimpleTreeSort*
:SimpleTreeSort [mode]
        Set the tree order to name, extension, mtime or size.  With no mode,
        cycle to the next one.  Directories always remain before files;
        mtime and size default to newest/largest first.

                                              *:SimpleTreeSortReverse*
:SimpleTreeSortReverse
        Reverse the current sort order while retaining directories first.

CUSTOM MAPPINGS ~
                                                *g:simpletree_mappings*
Every tree-buffer key can be remapped or disabled through a dictionary of
{key: action} pairs.  An empty action disables the key: >
  let g:simpletree_mappings = {'X': 'refresh', 'q': ''}
<
Available actions: open, expand, collapse, collapse_all, refresh,
toggle_hidden, toggle_git_ignore, close, root_here, root_up, root_prompt,
root_cwd, root_current, toggle_root_lock, copy, cut, paste, new_file,
new_folder, rename, delete, help, open_vsplit, open_split, open_tab,
preview, reveal_active, yank_name, yank_path, system_open, filter, find,
find_next, find_prev, sort_cycle, sort_reverse, bookmark_toggle,
bookmark_list, bookmark_next, bookmark_prev, mark_toggle, mark_siblings,
mark_clear.

The mark_toggle action installs a Visual-mode mapping on the same key as its
Normal-mode one, so remapping it moves both.

|g:simpletree_collapse_all_key| is still honored as a compatibility alias
for the collapse_all action.

USER EVENTS ~
                                                *simpletree-events*
SimpleTree fires |User| autocommands around tree lifecycle and file
operations.  Payload data is passed through g:simpletree_event: >
  autocmd User SimpleTreeFileCreated echom g:simpletree_event.path
<
Events: SimpleTreeOpen, SimpleTreeClose, SimpleTreeRootChanged,
SimpleTreeNodeOpened, SimpleTreeDirExpanded, SimpleTreeDirCollapsed,
SimpleTreeFileCreated, SimpleTreeFileDeleted, SimpleTreeFileRenamed,
SimpleTreeGitStatusUpdated, SimpleTreeFilterChanged.

7. WIDTH PERSISTENCE                       *simpletree-width-state*

When |g:simpletree_persist_width| is enabled, a resize updates the in-session
width immediately.  Disk writes are debounced by
|g:simpletree_width_persist_delay|; only the latest resize is written.  Closing
the tree or exiting Vim forces a final write.

Default paths:

- $XDG_STATE_HOME/simpletree/width when $XDG_STATE_HOME is set.
- ~/.local/state/simpletree/width on Unix otherwise.
- ~/vimfiles/simpletree/width on Windows otherwise.

8. BACKEND DIAGNOSTICS                         *simpletree-backend*

The backend supports: >

  simpletree-daemon --version
  simpletree-daemon --help
  simpletree-daemon --self-test
<
--self-test scans a directory in-process and checks the handshake, then prints
"ok".  install.sh runs it before replacing a working backend, so a build that
compiles but cannot walk a directory never reaches lib/.  Every daemon in the
simple* suite answers these three the same way.

Protocol mode uses one JSON object per line.  A client may send: >

  {"type":"ping","id":1}
<
The pong event includes protocol_version (currently 2), daemon_version, and
capabilities.  Protocol v2 adds: a `meta` flag on list requests (size, mtime,
is_symlink per entry), watch/unwatch requests with pushed fs_event records,
git_status requests with per-file codes and directory aggregation, and
streaming search requests.  Unreadable children degrade to warnings on the
final chunk instead of failing the listing, and non-UTF-8 names are listed
lossily with a non_utf8 flag.  Existing list and cancel requests remain
compatible; old clients ignore unknown event types.  Use
|:SimpleTreeVersion| for the executable discovered by Vim.

The daemon bounds concurrent blocking scans and keeps accepted requests
cancelable while waiting for a scan slot.  Protocol writes remain serialized;
queued records are coalesced before stdout is flushed.

9. FILE-OPERATION SEMANTICS                       *simpletree-safety*

- The workspace root cannot be cut, renamed, or deleted from the tree.
- Nested create names must remain relative to the selected destination.
- A directory cannot be pasted into itself or its descendants.
- Write targets, rename, and delete are constrained by the resolved workspace
  root, including symbolic-link boundaries.
- On Unix, copying a symbolic link forces cp -a.  Without a safe provider the
  operation is refused instead of dereferencing the link.
- Delete always asks for confirmation and prefers a supported trash command.
- Copy, overwrite, atomic move, and rename use sibling staging or backup paths
  and attempt restoration after failure.
- Unsaved buffers associated with source, target, or a directory subtree block
  destructive operations.
- y and Y always write Vim's unnamed register first.

These protections reduce data-loss risk but are not a cross-platform
transaction or crash-consistency guarantee.  SimpleTree does not currently
provide undo for file operations.

MARKED NODES ~
                                                        *simpletree-marks*
Marks are a transient "the next operation applies to these" set, unlike
bookmarks, which are a persistent "I care about this path" set.  <Space> marks
the node under the cursor and moves down a line; in Visual mode the same key
marks the whole selection (and unmarks it when it is already fully marked).
gm marks every visible node sharing the cursor node's parent directory, and gM
clears the set.  The count appears in the tree's statusline as marked:N and
each marked line ends with |g:simpletree_mark_symbol|.

While anything is marked, c, x and D act on the whole marked set instead of the
node under the cursor; every other key is unaffected.  Delete asks once, listing
up to five names plus "(and N more)", and then re-runs every per-path guard
described in |simpletree-safety| individually — an unsaved buffer or a path that
changed while the prompt was open fails that item only, and the failures are
reported together.

The workspace root can never be marked.  Marks are cleared when the root
changes and after a successful paste; a refresh keeps them but drops any whose
path no longer exists.

==============================================================================
10. TAB PAGES                                       *simpletree-tabpages*

One tree may be shown in several tab pages at once.  |:SimpleTree| always acts
on the current tab page: it opens a tree window there when the tab has none,
and closes only that window when it has one.  Every tab page shows the same
tree buffer, so the root, the expanded directories, the scan cache, marks and
Git status are shared and a second tab costs no extra scanning.

Because the tree is shared, |:SimpleTree| without an argument does not re-root
an already open tree when you open it in another tab; pass a directory or use
|:SimpleTreeReveal| to change what is shown.  Closing the last tree window ends
the session; closing one of several leaves the others working.

|:SimpleTreeClose| closes the current tab page's tree window, or every tree
window when the current tab page has none.  Width persistence
(|simpletree-width-state|) measures the tree window in the current tab page
only.

11. TROUBLESHOOTING                      *simpletree-troubleshooting*

BACKEND NOT FOUND ~

Run install.sh, then check: >

  :SimpleTreeVersion
  :SimpleTreeHealth
<
A nonstandard backend can be selected with |g:simpletree_daemon_path|.

INLINE SCAN ERROR ~

Fix the permission, path, or backend problem, then press R or run
|:SimpleTreeRefresh|.  Failed directories stop automatic retry storms until an
explicit refresh or a real directory timestamp change.

WIDTH IS NOT SAVED ~

Check that the parent of |g:simpletree_width_state_file| is writable.  Setting
|g:simpletree_width_persist_delay| to zero is useful for synchronous diagnosis.

DEFAULT MAPPING IS MISSING ~

SimpleTree does not overwrite an existing <Leader>e mapping.  Inspect it with
:nmap <Leader>e or map |<Plug>(simpletree-toggle)| explicitly.

DAEMON SUPERVISION                                    *simpletree-daemon*

The Rust daemon is managed by simplecore, the supervisor shared by the whole
simple* plugin suite. It is vendored into this repository at
autoload/simpletree/core.vim; that file is generated, do not edit it in place.

                                                  *simpletree-simplecore*
The bundle lives at https://github.com/beamiter/simplecore. Each plugin
carries its own copy so that installing this one alone is enough, and >

  make core-verify
<
checks every vendored file against the sha256 recorded in
.simplecore.manifest, failing the build when one has drifted. `make check`
depends on it. To change the supervisor, clone the bundle beside the plugins,
edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<

What it guarantees:

- Liveness is always read from |job_status()|. job_start() returns a job
  object even when the exec itself failed, so a daemon that cannot start is
  never mistaken for one that is running.
- A superseded daemon's late exit callback cannot clear the state of the
  replacement that already took its place.
- Output still queued when you stop the daemon is discarded, so an explicit
  stop cannot be undone by an event that was already in flight.
- A daemon that dies is restarted automatically with exponential backoff.
  If it keeps crashing, the supervisor reports it once and stops trying
  rather than respawning forever; :SimpleTreeRestart re-arms it.
- Requests are correlated to replies by id and can time out, so a wedged
  daemon never leaves a callback hanging.

:SimpleTreeHealth
        Report daemon path, run state, negotiated protocol and capabilities,
        uptime, crash and restart counts, and whether the crash-loop breaker
        has tripped, alongside this plugin's own diagnostics.

                                                      *:SimpleTreeRestart*
:SimpleTreeRestart
        Stop the daemon and start a fresh one. Clears the crash-loop breaker,
        so this is the way back after repeated failures.

                                                      *:SimpleTreeLog*
:SimpleTreeLog
        Open the daemon transcript in a scratch buffer: start and exit events,
        restarts, protocol handshakes, send failures and stderr.

vim:tw=78:ts=8:noet:ft=help:norl:
